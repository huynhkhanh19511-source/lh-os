# Capability Assessment

> Evaluate demonstrated capability through evidence, not self-description.

## Purpose

Capability Assessment compares observed performance against a defined capability model.

Its purpose is not to label a person or system as "good" or "bad".

Its purpose is to answer:

- What has actually been demonstrated?
- What evidence supports that conclusion?
- Where are the gaps?
- What should be tested next?

## Boundary

This Skill evaluates demonstrated capability.

It does not infer capability from titles, confidence, or intention alone.

```text
Evidence
   ↓
Assessment Criteria
   ↓
Capability Judgment
   ↓
Confidence
   ↓
Gap
   ↓
Next Development Test
```

## Core Principle

> Claim is not evidence.

Keep separate:

- Capability claim
- Observed behavior
- Evidence
- Interpretation
- Confidence

## Workflow

1. Define the capability being assessed.
2. Collect relevant evidence.
3. Map evidence to explicit criteria.
4. Identify demonstrated strengths and limitations.
5. Assign confidence to the assessment.
6. Identify the most important gap.
7. Define the next Runtime test.

## Output

A Capability Map containing:

- Capability
- Evidence
- Assessment
- Confidence
- Gap
- Development priority
- Next test

## Failure Modes

- confusing potential with demonstrated capability
- overweighting one successful example
- ignoring contradictory evidence
- using vague criteria
- turning assessment into identity judgment

## Runtime

Developing. Intended for repeated self-assessment and evidence-backed capability tracking.

> **Capability becomes credible when it survives contact with evidence.**
