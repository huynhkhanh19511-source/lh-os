# Gap Analysis

> Make the difference between current Reality and desired Reality explicit enough to choose an intervention.

## Purpose

Gap Analysis identifies meaningful differences between where a system is and where it needs to be.

A difference is not automatically a problem.

The Skill asks whether a gap matters, what causes it, and which intervention has priority.

```text
Current Reality
      ↓
Desired Reality
      ↓
Meaningful Difference
      ↓
Constraints / Causes
      ↓
Priority
      ↓
Intervention Hypothesis
```

## Boundary

Gap Analysis structures the decision space.

It does not automatically design the final solution.

## Core Principle

> Not every difference deserves intervention.

A useful Gap Analysis distinguishes:

- symptom
- underlying bottleneck
- constraint
- root cause hypothesis
- intervention opportunity

## Workflow

1. Define the current Reality.
2. Define the desired outcome or state.
3. Make the differences explicit.
4. Identify constraints and possible causes.
5. Estimate significance and urgency.
6. Prioritize the gap.
7. Form an intervention hypothesis.

## Output

A Gap Map containing:

- Current state
- Desired state
- Observed gap
- Constraints
- Cause hypotheses
- Priority
- Intervention hypothesis
- Unknowns

## Failure Modes

- defining an idealized desired state
- treating symptoms as root causes
- ignoring constraints
- assuming AI or technology is automatically the intervention
- prioritizing by visibility rather than impact

## Runtime

Developing. Intended for market fit, capability development, customer discovery, and system intervention.

> **A gap becomes useful when it changes what we do next.**
