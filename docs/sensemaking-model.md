# Sensemaking Model

LH OS treats Junior, Senior, and Architect as cognitive states of the same person moving through reality — not as fixed organizational ranks.

## Core progression

```text
Reality
  ↓
Reality Orientation
"What is this?"
  ↓
Structure Map
  ↓
Relationship Sensemaking
"How does it relate?"
  ↓
Relationship / Workflow Map
  ↓
System Formation
"What system should exist?"
  ↓
System / Architecture Map
  ↓
Runtime
  ↓
Feedback
```

## Three cognitive states

### 1. Reality Orientation — Junior State

The person enters an unfamiliar reality and first establishes what exists.

**Core question:** What is this?

Typical observations:

- Actors
- Objects
- Events
- Processes
- Constraints
- Existing artifacts

Primary artifact: **Structure Map**

The goal is not to design. The goal is to become oriented inside reality.

### 2. Relationship Sensemaking — Senior State

Once the structure is understood, the person identifies how the elements interact and how the workflow operates.

**Core question:** How does it relate?

Typical observations:

- Dependencies
- Actions
- Inputs and outputs
- Triggers
- Conditions
- Decisions
- Workflow relationships

Primary artifact: **Relationship / Workflow Map**

Structure Artifact Patterns help turn observed structure into reusable relationship representations.

### 3. System Formation — Architect State

Once structure and relationships are understood, the person can reason about the system that should be formed.

**Core question:** What system should exist?

Typical observations:

- System boundaries
- Control points
- Constraints
- Risk allocation
- Leverage
- Feedback loops
- Architecture choices

Primary artifact: **System / Architecture Map**

The Architect state is not simply drawing architecture. It is forming a system model from understood reality.

## Role is a state, not a person

```text
Same Person
    │
    ├── unfamiliar reality
    │       ↓
    │   Junior State
    │   Reality Orientation
    │
    ├── understood structure
    │       ↓
    │   Senior State
    │   Relationship Sensemaking
    │
    └── understood system
            ↓
        Architect State
        System Formation
```

A person may move between these states whenever entering a new reality. An experienced Architect can therefore begin a new customer engagement in the Junior state and progressively move toward the Architect state as context is acquired.

## Architectural Sensemaking loop

```text
              REALITY
                 │
                 ▼
       Reality Orientation
                 │
          Structure Map
                 │
                 ▼
     Relationship Sensemaking
                 │
       Relationship Map
                 │
                 ▼
        System Formation
                 │
          System Map
                 │
                 ▼
            Architecture
                 │
                 ▼
              Runtime
                 │
                 ▼
             Feedback
                 │
                 └──────────→ Reality
```

## Design principle

Architectural Sensemaking is not primarily about knowing more. It is about seeing progressively deeper structure:

```text
Junior    → Objects
Senior    → Relationships
Architect → System
```

The progression should be validated through artifacts and runtime evidence rather than assumed from job titles.
